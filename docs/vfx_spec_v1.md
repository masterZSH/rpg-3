# 《夜行录》动态特效与打击反馈规格 v1（vfx_spec_v1.md）

> 负责人：霍炜然（特效总监）　|　迭代档：美术反馈专项

## 2. 闪避

**触发**：`dodge`（起手）→ `dodgeSuccess`（无敌帧内规避任意伤害时，core 在 dealDamageToPlayer / resolveTelegraph 处发）。

| 阶段 | 表现与参数 |
| --- | --- |
| 起手（`dodge`，17t） | **残影拖尾**：位移期（0–9t）每 3 tick 在玩家当前位置投 1 个 ghost（kind=2 池已有），共 3 个；alpha 0.45→0 线性衰减，寿命 12 tick，半径=玩家碰撞半径 14px；颜色 = 纸白（正式色归 art_spec_v2）。位移 9t 后不再投（角色已停，避免"静止冒影子"） |
| 无敌帧可视化 | 残影存续期间玩家本体描边加 1px 白色高亮（仅 dodge 状态，读 `p.state==='dodge'`），退出即消失——给玩家"我现在无敌"的可读信号 |
| 成功（`dodgeSuccess`） | 屏幕边缘内收**白** vignette，alpha 0.5→0，6 tick；"闪！"小字 16px 金色于角色头顶 -40px；**无震屏**（§9 明确：避免与受击混淆） |
| 穿过 Boss 机制额外反馈 | 条件 = 同一逻辑 tick 的 drain 批内同时收到 `mechMiss` + `dodgeSuccess`（红机制被无敌帧躲过时 core 必然双发，见 combat.resolveTelegraph）。表现为：白 vignette 升级为**金白双色**（外圈金 alpha 0.35 叠加）、"闪！"字号 +4、额外 1 个金色 ring。⚠ 橙机制"走出范围"只发 mechMiss 不发 dodgeSuccess，天然不触发此加成——这正是想要的区分度；如需更稳可采纳 §9-A2 |
| 连续闪避 | dodgeCd 36t 天然互斥，无需去重；池上限兜底见 §7 |

## 3. 受击与死亡

### 3.1 玩家受击（`damage` kind=player）

| 项 | 参数 |
| --- | --- |
| 屏幕边缘红晕 | 径向 vignette，alpha = clamp(伤害/maxHp，0.15，0.6)，10 tick 内线性衰减到 0（现状 hurtFlash 实现保留，补齐"强度按伤害比"这一条——当前是固定值，改 addFloater 处读 e.value 与 p.maxHp） |
| 玩家闪红 | 沿用 `flashTicks=4`（core AUX）；本体填充→`playerHurt` 色；受击微抖保留 Math.random ±1px（渲染层允许） |
| 震屏 | 伤害 ≥8% maxHp → L1（3px/3tick）；≥12%（进 hurt 硬直）→ L2（4px/5tick）。阈值判断在渲染层用 e.value/p.maxHp 完成，不改 core |
| 机制命中 | `mechHit` 事件 → 红晕 alpha 0.55 + 震屏 L3（8px/8tick）+ 伤害数字 1.4× 字号（现状保留） |

### 3.2 敌人死亡（`death`，tier≠boss）

- **消散粒子**：碎裂 8 粒（elite 14 粒），四周放射 50–160 px/s，寿命 12 tick，重力 260px/s²；+ 1 圈扩散尘环（ring，12 tick，半径 6→60px）——池实现已有，参数不变。
- **尸体处理**：**不留尸体**。死亡帧敌人 active=false（core 现状即如此），由碎裂粒子 + 尘环承担"尸体感"；碎裂粒子落定（12 tick ≈400ms）后战场干净，符合"30–90 秒不累"的节奏。掉落物弹出由 loot 流程负责（视觉归 art_spec_v2，本文不管）。
- **连斩**：`killCombo`（value≥3）→ 顶部横幅由 HUD 层管（不归 canvas 粒子）；canvas 侧仅击杀点尘环半径 +10%/连击数（封顶 +50%），给"越杀越爽"的微小递进。

### 3.3 Boss 死亡（`death` tier=boss）

| 项 | 参数 |
| --- | --- |
| 分段崩解 | 碎裂 22 粒（现状）升级为**三波次**：0 tick 8 粒 / 6 tick 8 粒 / 12 tick 6 粒（渲染层 setTimeout 式的 tick 计数器，用粒子池寿命实现，不新增池）；粒子尺寸 ×1.5 |
| 全屏渐亮 | 白色全屏叠加 alpha 0→0.6→0，共 12 tick（复用 vignette 绘制通道，新增一条 whiteFlash） |
| 震屏 | L4（10px/12tick） |
| 时间放慢 0.4×/45 tick | **渲染层无法独立实现**（改的是逻辑 tick 节奏）→ 列入 §9-A3，由总监裁定。裁定前降级方案：仅做上述三波碎裂 + 渐亮，节奏感已可用 |

## 4. Boss 机制预警（优先级最高——"能不能看懂机制"）

**触发**：绘制读 `state.hazards[]`（kind=telegraph），转攻击瞬间读同批事件 `mechHit`/`mechMiss`；Boss 横幅读 `state.bossBanner` + `bossWarn` 事件。

### 4.1 地面判定区绘制（红 / 橙两档）

| 项 | 红（不可挡，必须无敌帧） | 橙（可走位脱出） |
| --- | --- | --- |
| 填充 | alpha 0.30 恒定（不脉冲——闪烁留给描边，双层信息不互相污染） | alpha 0.22 + **呼吸脉冲**：0.22→0.30，周期 18 tick 正弦 |
| 描边 | 3px，最后 12 tick 闪烁（6 tick/次，现状保留） | 3px，**不闪烁**（§9：表示可走位）；最后 12 tick 描边 alpha 0.9→0.4 线性压暗（"要打了"仍可读但不惊吓） |
| 收缩指示 | 描边随 remaining/total 向内收缩 6px（现状保留），红色改为**加速收缩**：进度曲线 p^1.5，让"快到了"有加速度感 | 线性收缩不变 |
| 方向辅助 | 无（红必须闪避，不给"走位"误导） | 保留 110px 推荐闪避方向箭头：从玩家中心指向判定区反方向，箭头 alpha 随 remaining 递减 0.8→0.3（实现：渲染层由 h.cx/cy 与玩家位置反算方向，纯只读） |
| 形状 | circle / line / cone 三种路径复用 drawShapePath 现状 | 同左 |
| 横幅 | `bossBanner` + `bossWarn`：预警起始震屏 L1（提示非惩罚，现状保留）；倒计时条由 HUD 层渲染 | 同左但无起始震动 |

### 4.2 预警转攻击瞬间（判定帧）

- **爆闪**：渲染层检测 telegraph `remaining ≤ 2` 时，在判定区内绘制一帧高亮填充（alpha 0.30→0.55，2 tick 内衰减到 0）——判定帧与视觉帧对齐，玩家能精确看到"这一下判了"。
- **判定结果反馈**：同批 drain 中 `mechMiss` → 判定区位置冒 6 粒灰白消散粒（落地扑空感）；`mechHit` → §3.1 机制命中全套（红晕 + L3）+ 判定区中心 1 个红色冲击环。
- **zone 延续**（点将台）：telegraph 结束同 tick core 生成 kind=zone 持续区，绘制规格：填充 alpha 0.18 + 虚线边（现状保留）；**危险区与安全区的差异靠色相**（红系=持续伤害，橙系=仅缓滞，颜色映射读 h.dps>0），避免玩家靠猜。

## 5. 环境动效（形态归 art_spec_v2，此处只锁性能参数）

雾 / 尘埃 / 萤火的**形态、色相、运动风格**由甄塑之在 art_spec_v2 定义；本节只给硬预算，超了就是我这边砍：

| 项 | 正常档 | 降档 |
| --- | --- | --- |
| 环境粒子数上限 | 同屏 **24**（从粒子总池 120 中划出固定配额，与战斗粒子**不互相挤占**：环境粒子用独立低优先级 acquire，池满时最先被战斗火花顶掉） | 8 |
| 更新频率 | 与渲染帧同频（60fps 插值），但**运动计算每 2 渲染帧一次**（结果缓存，绘制帧只用缓存值），省一半浮点 | 每 4 帧 |
| 生成方式 | 预热铺满（进战斗一次性 acquire 24 个，循环重生），运行期**零 new 零释放竞争** | 同 |

## 6. 震屏系统（统一参数表）

**实现**：维持 worldRenderer.shake 现状的"取大不叠加"原则（`px > shakeAmt` 才覆盖）——**连续触发幅度封顶 = 单次最大档 L4 的 10px**，永不超过；方向用 Math.random 全向（渲染层允许）。新增：**晕动症友好总开关**（settings 面板加一项"减少屏幕震动"，读 `meta.settings`，不改 core state 结构——settings 已有通道），开启后所有档位幅度 ×0，但 vignette / 粒子 / 顿帧**全部保留**（反馈不消失，只去位移）。

| 档 | 幅度 | 时长 | 触发事件 |
| --- | --- | --- | --- |
| L0 | 0 | 0 | 普攻命中、闪避成功、拾取（§9 明确无震） |
| L1 轻震 | 2–3px | 2–3tick | 暴击（2/3）、玩家受伤 ≥8%（3/3）、bossWarn 起始（3/2）、替换仙品（5/5→归 L2） |
| L2 中震 | 4–5px | 5–6tick | 高耗技能命中（碎岳/千刃/万灵 4/5）、升级（5/6）、精英击杀（6/6） |
| L3 重震 | 8px | 8tick | 机制命中（mechHit） |
| L4 特重 | 10px | 12tick | Boss 死亡 |

规则：同帧多事件取最高档；低档正在进行时被高档覆盖（现状行为）；**反向亦然**——高档进行中低档不得缩短其时长。

## 7. 性能预算

### 7.1 同屏粒子数（对象池总量 160 预分配，现状保留）

| --- | --- | --- |
| 正常 | **120**（balance.fx.particleMax） | 战斗粒子优先；环境 24 + 事件粒子 96 |
| 降档 | **40**（particleMaxLow） | 环境砍到 8；暴击/击杀粒子保量，普攻火花减半 |

超预算**丢弃新粒子、保存量**（现状 acquire 语义正确，保留）。

### 7.2 创建成本要求（写码规约）

- 粒子 / 飘字 / ghost / 环 / 事件对象：一律预分配池 + `active` 标记，**运行时禁止 `new`、禁止 splice**（tech §6，steady state 堆分配 <1KB/帧）。
- 每个特效入口必须是"取池对象 + 填字段"两条语句量级；单次事件最多 acquire 24 个粒子（Boss 崩解三波合计也 ≤22），超出预算自动截断（acquire 返回 null 即弃，已实现）。
- 渐变 / 路径对象复用：背景渐变每帧 createLinearGradient 是现状技术债，本次迭代**必须**改为初始化时建一次缓存复用（vignette 同理，两个径向渐变缓存复用，alpha 用 globalAlpha 调制）。
- 顿帧 / 慢放等时间操纵只允许作用于渲染侧计时器，禁止触碰 loop 补步逻辑。

## 8. 验收点（≤4，可肉眼/可测量）

1. **V1 命中时效**：录帧逐帧检查——普攻/技能/暴击命中事件发生的渲染帧起，**100ms（3 渲染帧）内**必须出现可见反馈（闪白或火花首帧）；暴击额外在 2 帧内可见顿帧（粒子静止）。
2. **V2 预警可读性**：三个 Boss 全机制实录——红区在触发前 ≥12 tick 有可辨闪烁、橙区呼吸脉冲与方向箭头可见；肉眼回放（不暂停）能正确说出"红的要闪避、橙的走出去"，判断正确率 100%。
3. **V3 震屏封顶**：连打脚本同时触发暴击+机制命中+精英击杀，逐帧测位移——任意时刻画布位移 **≤10px**，且高档时长不被后续低档截短。
4. **V4 预算与降档**：`?q=low` 下稳态粒子活跃数 ≤40、无运行时 `new`（DevTools allocation timeline 采样 10s 堆增长 <10KB）、逻辑 tick 计数与高档完全一致；开关"减少屏幕震动"后位移为 0 但 vignette/粒子反馈仍在。
